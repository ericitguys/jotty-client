# Card-Wall Main View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the client's full-width stacked list rows (Notes + Checklists tabs) with the jotty-web-style card wall — side-by-side cards (notes = masonry columns, checklists = uniform grid with a completion progress bar) — and make the editor/checklist view replace the wall full-width when an item is open (back button returns), at every window width.

**Architecture:** Pure frontend change. The two list components restructure their row DOM into card head/body/foot regions (all existing class names that tests pin ride along unchanged); styles.css swaps the single-column row list for a CSS multi-column masonry (notes) and a uniform responsive grid (checklists), plus moves the back button out of the phone-only media query so the full-swap (already the phone's visual behavior since 0.24) becomes the behavior at every width. App.tsx stops rendering the list section while an item is open (true unmounting — the phone's CSS-hide would be unverifiable in jsdom).

**Tech Stack:** React 19 + TypeScript + Vite frontend, vitest + RTL (jsdom), WebKitGTK headless probes for real-engine layout verification (the shipped desktop engine). No new dependencies. No Rust changes.

**Spec:** `docs/superpowers/specs/2026-10-06-card-wall-main-view-design.md` — read it first; it carries the upstream reference facts (fccview/jotty card mode), the out-list, and the verification requirements. Conflicts resolve against the spec.

        {checklists.map((c) => {

                className="row-del"

                title="Delete"
